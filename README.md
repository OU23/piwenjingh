# tool-box 前端（toolbox-frontend）

本目录为 tool-box 工具管理箱的**前端工程**，单独可运行、可构建，不依赖任何一方的后端实现——所有接口调用以
`docs/接口契约.md`（当前 v1.1）为唯一依据，基址可通过配置切换。

## 一、环境要求

| 项 | 版本 | 校验命令 |
| --- | --- | --- |
| Node.js | **20.19.x**（基线 20.19.1） | `node -v` |
| npm | 随 Node 附带（基线 10.x） | `npm -v` |

> 版本以 `docs/技术选型.md` §三 为唯一基准，请勿使用其他 Node 大版本。

## 二、安装与启动

```bash
# 1. 安装依赖（首次或依赖变更后）
npm install

# 2. 启动开发服务器
npm run dev
```

启动后访问 **http://localhost:5173**。

停止：在终端按 `Ctrl + C`。

> `npm run dev` 会**常驻占用终端**（热更新需要），这是正常现象；`npm run build` 则是**跑完即退**的一次性命令，
> 两者表现不同，不是卡死。

## 三、配置项

配置通过环境变量注入，文件已提交，**不含任何密钥**。

| 文件 | 用途 |
| --- | --- |
| `.env.development` | 开发期（`npm run dev` 读取） |
| `.env.production` | 构建期（`npm run build` 读取） |
| `.env.local` | 个人本地覆盖，**不提交**（如需临时改基址） |

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 空 | 接口基址。**留空 = 同源**，请求走同源路径 |
| `VITE_PROXY_TARGET` | `http://localhost:8080` | 开发期代理目标（仅 `npm run dev` 生效） |
| `VITE_DEV_PORT` | `5173` | 开发服务器端口 |

### 三种运行方式

**① 本地后端（默认）** —— 不修改任何配置，直接 `npm run dev`：

```bash
VITE_API_BASE_URL=            # 同源
VITE_PROXY_TARGET=http://localhost:8080   # 由 Vite 代理把 /api 转发到后端
```

**② 直连远端后端** —— 在 `.env.local` 写入绝对地址（此时不经过代理）：

```bash
VITE_API_BASE_URL=http://其他机器的地址:8080
```

**③ 生产构建 + 反向代理** —— 构建时 `VITE_API_BASE_URL` 留空，由部署侧把 `/api` 转发到后端：

```bash
VITE_API_BASE_URL=
```

> **基址切换只改配置、不改代码**（验收 A2）。这也是前端不绑定任何一方后端实现的前提。

## 四、常用命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动开发服务器（端口 5173，常驻） |
| `npm run build` | 类型检查 + 生产构建，产物在 `dist/` |
| `npm run preview` | 本地预览构建产物 |
| `npm run typecheck` | 仅类型检查（`vue-tsc --noEmit`） |
| `npm run lint` | 代码检查 |
| `npm run test` | 运行全部测试 |
| `npm run test:unit` | 仅运行单元测试（`tests/unit`） |
| `npm run test:watch` | 测试守护模式（边改边跑） |

**单跑某个文件或用例**（`test:unit` 后面接参数会退化为跑全部，请直接用下列写法）：

```bash
npx vitest run tool-query          # 按文件名关键字
npx vitest run -t "续传"            # 按用例名关键字
```

## 五、构建产物

`npm run build` 产物在 `dist/`，为纯静态资源，可由任意静态服务器或反向代理托管。

- 前端路由为 history 模式，**部署侧需将未命中的路径回退到 `index.html`**（否则刷新子页面会 404）。
- 若前后端跨源部署，反向代理需同时转发 `/api` 与上传分片相关路径。

## 六、常见问题

> **下载行为（契约 v1.19 起）**：点「下载」→ 前端向后端**签发**一个短时效下载地址 → 用 `<a>` **导航下载**。文件在**对象存储**时浏览器**直连 OSS**（字节不过后端），在**本地**时仍由后端返回。进度 / 暂停 / 续传由**浏览器原生下载器**接管 —— 自研流式写盘（FSA）与"整包读入"降级路径**已退役**，前端**不再依赖**安全上下文。

| 现象 | 原因与处理 |
| --- | --- |
| 登录时报「无法连接服务器，请确认后端服务已启动」 | 后端未启动或基址配置有误。确认后端已监听，且 `.env.local` 的基址正确 |
| 页面停留在登录页，直接访问其他地址被弹回 | 未登录是预期行为：除登录与系统初始化外，其余页面均需登录 |
| 管理菜单看不到 | 当前账号缺少对应权限点。菜单与按钮按权限显隐，无权限即不显示（非灰置） |
| 点「下载」后没有进度条 / 无法暂停续传 | **预期行为**：进度与续传由浏览器原生下载器接管（见本节目首的「下载行为」） |
| 点「下载」提示「对象存储暂不可用」 | 文件已落对象存储，但 OSS 侧异常（凭据 / 网络 / 桶权限）。可稍后重试；**不影响**登录、检索与本地文件下载 |
| `node -v` 不是 20.19.x | 请切换到基线版本；版本不一致导致的报错优先排查版本 |
